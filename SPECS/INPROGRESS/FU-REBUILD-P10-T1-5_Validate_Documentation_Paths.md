# FU-REBUILD-P10-T1-5: Validate and Fix Documentation Paths for Local-Running MCP Server with Web UI

## Overview

Documentation for the "manual installation" / "local development" scenario contains incorrect or misleading paths to the `mcpbridge-wrapper` executable. The `install.sh` script installs the package via `pip3 install -e .` and creates a `~/bin/xcodemcpwrapper` shell wrapper that calls bare `python3 -m mcpbridge_wrapper`. This fails when the package is installed inside a `.venv` (as recommended) because the system `python3` cannot find the module.

Additionally, DocC Installation Method 4 instructs users to `cp src/mcpbridge_wrapper/cli.py ~/bin/xcodemcpwrapper`, which cannot work because `cli.py` imports from other package modules.

## Root Cause

The `~/bin/xcodemcpwrapper` wrapper generated by `install.sh` uses:
```bash
exec python3 -m mcpbridge_wrapper "$@"
```

This calls whatever `python3` resolves to in `$PATH` (typically system Python). If the package was installed via `pip install -e .` inside a `.venv`, the system Python cannot find `mcpbridge_wrapper`.

By contrast, `make install` (which does `pip install -e .`) creates `.venv/bin/mcpbridge-wrapper` with a correct shebang pointing to the venv Python — this path always works.

## Deliverables

### D1: Fix `scripts/install.sh` to use venv Python

Update the generated wrapper script to use the venv Python interpreter instead of bare `python3`:

```bash
#!/bin/bash
exec /path/to/XcodeMCPWrapper/.venv/bin/python3 -m mcpbridge_wrapper "$@"
```

Or better: detect and embed the correct Python path at install time.
